# 第 7 章 多章节一致性保持

> **教学目标**：学完本章，你写的长篇在第 30 章后依然不丢设定、不复活角色、不错时间线——靠的是"设定回写 + 滑动窗口摘要 + 三段式检查"三层防线，而不是赌模型记性好。

---

## 7.1 为什么长篇必然"失忆"

单核大模型写长篇，剧情暴走、人设崩塌是必然，不是概率。多 Agent 架构一文给出两个根因：

1. **中间迷失（Lost in the Middle）**：几十章前的伏笔在注意力里被稀释，模型越写越"只看得到最近几章"，于是角色复活、地点漂移、时间线错乱；
2. **概率回归**：next-token 生成永远往最安全的方向靠，不召回设定它就会用陈词滥调填坑。

所以结论只有一个：**一致性不能靠模型记忆，要靠外部系统**。本章的三层防线全部来自素材库里验证过的工作流（多 Agent 架构、34 本小说经验、WenShape/NovelGenerator 等仓库），按成本从低到高排列，先做第一层就能解决 80% 的问题。

## 7.2 三层防线

**第一层：设定回写（外部事实库）**

把"模型记不住的东西"搬到文件里：角色卡、世界观卡、时间线、伏笔表。每次写新章前，把相关条目**摘抄进提示词**（不是全文丢进去，是挑选本段涉及的）。对应工具：WenShape 的事实表、AI_NovelGenerator 的设定工坊、FeelFish 的上下文管理——本质都是同一件事：设定存在工具里，写作时引用，随写随更。

**第二层：滑动窗口摘要**

长篇上下文的正确喂法不是"把前 30 章全文塞进去"，而是维护**章节摘要**：每章写完后，用轻量模型把它压成 200 字结构化摘要（记事件进展、新设定、新伏笔、状态变化）。写第 N 章时只喂"全局大纲 + 第 N-3 至 N-1 章摘要 + 本章任务"。多 Agent 架构与 NovelGenerator（持久故事记忆 + 场景交接）都是这个思路——信息密度高、上下文干净，模型不会迷失。

**第三层：写前/写中/写后三段式检查**

- **写前**：把本章涉及的 {角色 / 地点 / 时间 / 未回收伏笔} 清单摆进提示词，让 AI 先引用设定再动笔；
- **写中**：每章在"干净上下文"里单独跑，写完立刻回写进度（34 本小说经验的 loop.md 工作流）；
- **写后**：跑一轮矛盾修正清单（模板 C），或用脚本对名称、时间线做程序化检查（CometAPI 工作流的做法），发现问题再改，而不是写完全书才查。

## 7.3 可直接复制的提示词模板

### 模板 A：章节摘要生成器（滑动窗口核心）

```text
以下是长篇小说第 {N} 章的正文：{粘贴本章正文}
请把它压缩成 {200} 字以内的结构化摘要，按以下格式输出：
- 事件进展：{2–3 句，本段剧情发生了什么，结局状态}
- 新增设定：{本章新出现的设定，没有则写"无"}
- 新增伏笔：{本章埋下的伏笔，没有则写"无"}
- 状态变化：{角色状态/关系/装备/势力变化，逐条列出}
- 章末钩子：{本章结尾的悬念，一句话}
规则：只记"变化"不记"重现"；已在前几章摘要中出现过的设定不要重复写。
```

### 模板 B：写前设定召回单

```text
我要写第 {N} 章：{本章任务/节拍}
动笔前，先按以下清单从设定集中召回相关内容，然后输出一份"写前设定包"：
1. 出场角色：{列出角色名}——引用每个人物卡中的：当前状态、关系、说话声音（口头禅/句式）；
2. 地点：{列出地点}——引用世界观卡中的方位、建筑、环境特征；
3. 时间线：{本章发生在哪个时间点}——距上一章过去多久，季节/时辰是什么；
4. 未回收伏笔：列出设定集中所有与本章相关的未回收伏笔，注明埋设章节；
5. 禁忌：本段禁止出现 {如：现代科技词汇 / 角色 A 出现在他不在场的场景 / 使用已死亡角色}。
输出设定包后，再开始写正文；正文中不得出现设定包之外的新人名、新地名、新能力。
```

### 模板 C：矛盾修正清单（写后检查）

```text
你是长篇小说的连续性审稿人。请审查以下材料，输出矛盾清单：
前情摘要：{粘贴最近 3 章摘要}
本章正文：{粘贴刚写完的章节}
检查维度：
1. 角色矛盾：姓名/年龄/关系/能力/伤疤/口头禅是否与设定卡一致，角色是否"复活"；
2. 时间线矛盾：日期/季节/距上次事件天数是否自洽；
3. 地点矛盾：方位/建筑/环境是否与世界观卡一致；
4. 伏笔矛盾：本章是否错误回收了未到期的伏笔，或与已回收伏笔冲突。
输出格式（每行一条）：[维度] 章节位置 | 矛盾内容 | 建议修正 | 影响等级（高/中/低）
没有矛盾的维度写"无"。只列矛盾，不重写正文。
```

### 模板 D：设定回写更新

```text
以下是本章正文：{粘贴本章正文}
请对照现有设定集更新条目，输出增量修改建议（不要重写整个设定集）：
1. 新增条目：{本章新出现的角色/地点/能力/势力，给出要写入设定卡的字段}
2. 修改条目：{本章改变了既有设定的，给出修改后的字段值}
3. 伏笔表：{本章新埋的伏笔加入表：内容 | 埋设章 | 计划回收章；本章已回收的伏笔标记"已回收"}
4. 状态表：{主要角色当前状态一行一个：角色 | 位置 | 状态 | 备注}
输出为可直接追加到设定集文件的 markdown 块。
```

## 7.4 操作步骤

1. **建设定集目录**：在项目里建 `lore/` 文件夹（或使用工具自带的设定库），存放人物卡、世界观卡、时间线、伏笔表（第 3 章已建好人物卡/世界观卡，这里补伏笔表和状态表两张）。
2. **每章动笔前**：跑模板 B 生成写前设定包，把设定包放进场景写作任务书（第 5 章模板 A）一起发给 AI。
3. **每章写完**：跑模板 A 生成 200 字摘要，存进 `summaries/NN.md`；再跑模板 D 回写设定集。两步加起来不到一分钟，但这是 30 章不崩的根基。
4. **每 3–5 章**：跑一次模板 C 矛盾清单，把"高"级矛盾当场修掉；攒到全书写完再修，成本会翻几倍。
5. **工程化进阶**：用 NovelGenerator（本地持久故事记忆 + 场景交接）或 Novels 多 Agent 管线，让摘要与召回自动化；用 WenShape 的事实表做上下文自动评分排序。

## 7.5 常见坑 + 解决方法

| 坑 | 现象 | 解法 |
|---|---|---|
| 只靠模型记忆 | 上下文很大但写到 20 章还是丢设定 | 上下文长≠记得住；设定必须落到外部文件，写前显式引用（第一层防线） |
| 摘要写得太细 | 摘要越长模型越抓不住重点 | 压到 200 字以内，只记"变化"不记"重现"，格式固定（模板 A） |
| 回写滞后 | 设定集还是 10 章前的，新章设定全乱 | 每章写完立刻跑模板 D，别攒批处理 |
| 写完不检查 | 角色复活、时间线错乱直到完稿才发现 | 每 3–5 章跑模板 C，当场修"高"级矛盾 |
| 一次喂太多上下文 | 模型被前文淹没，本段任务执行变形 | 滑动窗口：只喂全局大纲 + 最近 3 章摘要 + 本章任务 |
| 修矛盾时重写全文 | 修一处引入三处新错 | 模板 C 只出清单，修复时按"最小改动"原则逐条改（第 9 章会展开） |
