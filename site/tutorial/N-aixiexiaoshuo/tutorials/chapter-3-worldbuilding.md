# 第 3 章 世界观与角色设定

> **教学目标**：学完本章，你能建立一套"人物卡 + 世界观卡"的设定集（Story Bible / Codex），让 AI 在几十章内保持人设、时间线、世界规则不崩。

---

## 3.1 为什么必须有设定集：长篇失忆的根源

AI 写长篇必然出两类问题（多 Agent 架构文章给出了根因）：
1. **中间迷失（Lost in the Middle）**：几十章前埋的伏笔在超长上下文里注意力被稀释，模型会漏掉甚至让角色"复活"；
2. **概率回归**：模型总往最安全、最套路的方向靠——写到 4 万字后主角瞳色变了两次、第 5 章死的人第 12 章还在吃饭，都是这个原因（Claude 写作助手手册点名）。

**解法不是靠模型记性好，而是把设定放到模型之外**：建一个集中式设定集，每次写作前喂给它相关条目。所有高 star 工作流（WenShape、AI_NovelGenerator、FeelFish、灵蟹创作）本质都是干这一件事。

## 3.2 设定集的标准结构

参照 Claude 写作助手手册的 Story Bible 结构（国内 WenShape 的卡片系统与之等价，只是存储为 YAML 文件）：

```text
设定集（Story Bible）/
├─ Characters/    人物：主角/反派/配角，每人一张人物卡
├─ World/         世界观：地点、魔法体系/科技规则、历史、世界规则
├─ Plot/          大纲：主线、时间线、线索/伏笔台账
├─ Style/         文风：叙事声音、主题、禁词表
└─ Chapters/      章节：各章正文 + 摘要（用于回看）
```

**人物卡必填字段**（来自 Claude 手册 + CometAPI 角色档案，合并后的最小集）：

```text
- 基本信息：姓名/年龄/身份/外貌（写死，别让 AI 改）
- 性格：核心特质、优缺点
- 恐惧与欲望（驱动行为的内核）
- 背景：出身、关键经历
- 说话风格与口头禅（区分角色的第一武器）
- 情感弧：弧光起点 → 终点（他在这本书里要变成什么样）
- 一致性注意事项：容易写崩的点（如"左撇子""对 X 过敏"）
```

**世界观卡**采用"描述优先（description-first）"写法（WenShape 的做法）：一条设定用一段完整描述记录，而不是零散规则列表，这样 AI 更容易理解引用。**世界物理规则和势力平衡**是必须写死的两项（做故事架构师文章强调），它们是 AI 不瞎编的底线。

**文风卡**（WenShape 单独建 `cards/style.yaml`）：叙事视角、句式偏好、禁词表（第 2 章的 AI 高频词黑名单放这里）。

## 3.3 两个关键技巧

**人格锚点**（做故事架构师文章）：用一句话定义角色核心特质，例如"极度理性但严重失眠""表面疯癫实则对数字敏感"。每章写作前喂入这句，AI 就不会把角色写成同一张脸。在此基础上你再注入情感细节（把"主角因风险拒绝"改写为"盯着地图手指微颤摇头"）。

**情感弧图**（CometAPI 文章）：写大纲时给主角定 30%/60%/100% 三个情绪落点——30% 处第一次打击、60% 处谷底/假胜利、100% 处终极转变。AI 逐章写作时按落点走，角色成长就不会变成"一路平"或"突兀黑化"。

**防 AI 套路名**（34 本小说经验）：AI 起名高度模板化——女角色爱叫 Lyra/Elara，男角色爱叫 Kyle，反派爱以 Mal- 开头，还执着"低语森林"和"开学校"开局。人物卡里直接写死名字，并在提示词里主动排除这些套路。

## 3.4 可直接复制的提示词模板

### 模板 A：人物卡生成

```text
你是一位资深小说设定策划。请为以下角色建立完整人物卡，输出为可直接存档的 markdown：

角色定位：{主角/反派/关键配角}
一句话原型：{如：表面疯癫实则对数字敏感的占卜师}
所属作品背景：{一句话世界观，如：架空朝堂权谋世界}

人物卡必须包含：基本信息（姓名/年龄/身份/外貌）、性格核心特质、
恐惧与欲望、背景出身、说话风格与口头禅、情感弧（起点→终点）、
一致性注意事项（列出最容易写崩的 3 个点）。
注意：姓名不要使用 Lyra/Elara/Kyle/Mal- 开头等常见 AI 套路名；
外貌必须具体到可核对（瞳色、疤痕、标志性物件）。
```

### 模板 B：世界观卡

```text
请以"世界观架构师"身份，为我的小说建立世界观卡，输出为可直接存档的 markdown。
设定基线：{如：魔法体系需以"等价交换"为唯一规则；王朝三分天下；禁止出现现代科技}

世界观卡必须包含：
1. 世界一句话定位与地理概况（主要地点，各一句话）；
2. 核心规则体系（力量/科技/魔法规则的运作方式与代价，必须具体到可检查）；
3. 势力格局（主要势力、目标、彼此关系）；
4. 历史大事记（影响当前局势的 2–3 个历史事件）；
5. 常识禁忌（这个世界里"不可能存在"的事，防 AI 编造）。
每条设定用完整描述句记录，不要用零散标签。
```

### 模板 C：人格锚点

```text
用一句话定义角色 {角色名} 的核心人格锚点，
要求：一个核心特质 + 一个与之冲突的细节（如"极度理性但严重失眠"）。
这句话将在每章写作前喂给 AI 稳定行为逻辑，所以必须：
- 能被任何场景的行为描写直接检验；
- 不包含外观描写（外观放人物卡）。
```

### 模板 D：情感弧规划

```text
以"剧作顾问"身份，为角色 {角色名} 规划全书情感弧，共 {章节数} 章。
请给出：
1. 弧光起点状态（开头他是怎样的人）；
2. 30% 处（第 {X} 章）：第一次打击/转变事件；
3. 60% 处（第 {Y} 章）：谷底或假胜利；
4. 100% 处（第 {Z} 章）：终极转变后的状态；
5. 每段用一句话说明情感落点与对应关键事件。
```

## 3.5 操作步骤

### 路径 1：通用助手 + 本地文件（最通用）

1. 新建一个专门会话（如 Kimi 项目 / Claude Projects），建 `设定集/` 文件夹。
2. 用模板 A、B 逐个人物、逐条世界观生成卡片，存成 md 文件（`角色-林晚.md`、`世界观-魔法体系.md`）。
3. 每章写作前，把"本章出场人物的卡 + 相关世界观条目 + 上一章结尾"一起贴进提示词（模板 B 第 2 章）。
4. 每写完一章，用 1–2 句话回写该章摘要进 `Chapters/`，并更新人物状态（"第 5 章后林晚左臂受伤"）。

### 路径 2：FeelFish / 灵蟹创作（专用工作台，条目化设定）

1. 在工具里逐条新建：人物、地点、世界观规则、支线，每条一个条目（FeelFish 的上下文管理器 / 灵蟹创作的项目结构）。
2. 写作时提示词里只需引用条目名（如 `@人物-林晚`），不必重复粘贴全文。
3. 想保留的支线单独建条目，生成场景节拍时引用它。

### 路径 3：WenShape（本地开源，卡片 + 百科导入）

1. 下载 Windows Release 包双击启动（或 `git clone` 后 `start.bat`）。
2. 用"人物卡/世界观卡/文风卡"卡片系统建档（数据存 YAML，可版本管理）。
3. 同人向：用"搜索→预览→抓取→提案"流程，从萌娘百科/Fandom/Wikipedia 批量导入角色与世界观，先以 proposal 形式预览，确认后才写入项目。

## 3.6 常见坑 + 解决方法

| 坑 | 现象 | 解法 |
|---|---|---|
| 设定散落在聊天记录 | 换会话后 AI 完全不记得设定 | 设定全部落盘成 md/YAML 文件，每次写作前显式喂入 |
| 角色外观漂移 | 瞳色/发型/疤痕变来变去 | 人物卡写死外观 + 一致性注意事项，写作前必带 |
| 死人复活、时间线错乱 | 第 5 章死的第 12 章还吃饭 | 维护 `时间线.md`，每章回写；写作前核对（第 7 章展开） |
| AI 起名全是套路 | Lyra/Kyle/低语森林 | 名字写死在人物卡，提示词里主动排除套路 |
| 世界观规则不写死 | 魔法体系前后矛盾 | 世界观卡用"描述优先"写清规则与代价，作为防编造底线 |
| 人物弧光平 | 角色从头到尾一个样 | 用情感弧图定 30/60/100 三落点，逐章按落点推进 |
| 新引入设定不归档 | 本章新增的地点下章就忘 | 写后把新元素回写设定集（Claude 手册"写后"步骤） |
