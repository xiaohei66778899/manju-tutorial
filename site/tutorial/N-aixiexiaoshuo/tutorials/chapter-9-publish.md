# 第 9 章 完稿与发布

> **教学目标**：学完本章，你能在全书完成后跑一轮"无情审稿 + 最小改动修复"，把 Markdown 转成可发布的格式；写付费文时，知道怎么用付费卡点定位和完读率数据复盘。

---

## 9.1 完稿不是终点，是审稿起点

全书写完 ≠ 可以发。34 本小说经验里最重要的一步恰恰在最后：**另起一个干净上下文，让 AI 当无情编辑**，输出全书的问题清单；再开一个新上下文，按"最小改动"原则逐条修复。为什么必须另起上下文？因为写正文的上下文里全是前文残影，模型只会自我表扬；干净的上下文才能跳出文本看文本。

CometAPI 工作流给了专业编辑的六遍 pass 顺序：**起草 → 结构（情节/弧光）→ 角色一致性 → 行级 → 校对 → 试读**。AI 写完初稿后，你自己按这个顺序跑 5–6 遍审查，每遍只干一件事，不要混在一起。

## 9.2 审稿与修复的正确姿势

1. **无情审稿（模板 A）**：让 AI 输出矛盾、剧情漏洞、时间线问题清单，按严重程度排序。只出清单，不重写——审稿和修复必须分开，否则 AI 会边找边改、越改越乱。
2. **最小改动修复（模板 B）**：拿着清单逐条问 AI"这条怎么改最小"，改完回填。修一处只动一处，不顺手重写周边。
3. **程序化检查**：名称/时间线这类机械问题用脚本扫（脚本检查所有角色名是否拼写统一、日期是否倒挂），比人眼可靠。
4. **试读反馈（模板 C）**：让 AI 以目标读者视角读关键章节，报告读感而不是挑错——节奏、悬念、代入感、付费意愿。

## 9.3 付费文的卡点与复盘

如果目标是付费连载（知乎盐选、番茄等），盐选实操手册的核心逻辑：**付费节点要卡在高潮将到未到的最痒处**——真相将揭、阴谋将成时断更。三个动作：

1. **定位卡点（模板 D）**：让 AI 找出前 3–4 章里最适合断更的位置；
2. **按数据迭代**：发布后盯着**完读率、互动率、评论区催更/开骂**——催更说明卡点对了，开骂弃坑说明爽点密度不够；
3. **前 1000 字定生死**：开篇必须直接进冲突、抛最强悬念，拒绝"我叫 XX"式平铺（模板 C 可配合检查开篇）。

## 9.4 平台发布要点（起点 / 番茄 / 知乎盐选差异）

不同平台的"作品"根本不是同一种东西，发布前先选对赛道。通用规则如下（具体政策以各平台最新公告为准）：

| 平台 | 读者与题材倾向 | 收益模式 | 关键指标 | AI 辅助的适配点 |
|---|---|---|---|---|
| 起点中文网 | 长篇追读型读者，玄幻/都市/历史等传统网文题材 | VIP 订阅制（按章收费） | 追读率、订阅比、月票 | 卷纲/章纲管理、稳定日更产能（第 4 章大纲 + 第 5 章场景分块） |
| 番茄小说 | 免费阅读、下沉流量，节奏快的爽文 | 免费阅读 + 广告分成 | 完读率、留存、翻页率 | 开篇 3 章完读率优先，爽点密度拉满、单章短平快 |
| 知乎盐选 | 会员制付费短篇，情感/职场/悬疑类选题 | 盐选会员分成（买断或分成） | 付费转化率、卡点质量 | 付费卡点定位（本章模板 D）+ 前 1000 字强悬念（第 2 章模板 C） |

要点：**起点拼追读（读者跟不跟）、番茄拼完读（读者读不读完）、盐选拼卡点（读者掏不掏钱）**。写之前先定平台，因为开篇节奏、章长、卡点位置全部跟着平台走。

格式导出（Markdown 主稿 → 多格式）：

```bash
# Pandoc 一键导出（34 本小说经验的发布管线）
pandoc novel.md -o novel.epub --toc        # EPUB：电纸书/自出版发行
pandoc novel.md -o novel.txt               # TXT：投稿/备份（起点、番茄均支持）
pandoc novel.md -o novel.pdf               # PDF：打印/留档
# 注意：epub 建议先合并封面（--epub-cover=cover.jpg），正文插图路径要相对主稿所在目录
```

## 9.5 可直接复制的提示词模板

### 模板 A：全书无情审稿（evaluation）

```text
你是本书的无情编辑，目标是把这本书改到能出版。请审阅：{粘贴全书或全部章节摘要}
输出《审稿报告》，按严重程度排序，格式：
- 【致命】必须修：{矛盾/剧情漏洞/逻辑断裂/角色 OOC，逐条列出：位置 | 问题 | 为什么是问题}
- 【重要】应该修：{节奏问题/悬念失效/伏笔未回收/重复描写}
- 【建议】可以修：{行级瑕疵/用词重复/AI 高频词}
- 【亮点】保留：{哪些段落最好，修改时不得动}
只输出报告，不修改任何正文。
```

### 模板 B：最小改动修复

```text
以下是我书中的一处问题（来自审稿报告）：{粘贴问题条目}
请给出修复方案，遵守：
1. 最小改动：能改一个词就不改一句，能改一句就不改一段；不重写周边内容；
2. 每处问题给出：修改位置 | 原文 | 修改后 | 为什么这样改；
3. 如果此问题牵一发而动全身（改了这里会影响后面 N 处），先列出受影响位置清单再动手；
4. 修复后必须自查：本次修改没有引入新的时间线/人设矛盾。
```

### 模板 C：试读反馈模拟

```text
请以 {目标读者，如：喜欢都市爽文的 25 岁上班族} 的视角，试读以下章节：{粘贴章节}
输出试读报告：
1. 读感曲线：从第几段开始觉得无聊/吸引/想弃书，标注位置；
2. 悬念与钩子：本章结尾是否想立刻看下一章（是/否，为什么）；
3. 代入感：哪些地方觉得假/出戏，哪些地方代入感强；
4. 付费意愿：如果这是付费章节的第 {N} 章，你愿不愿意继续付费（给 0–10 分）；
5. 一句话总评。
```

### 模板 D：付费卡点定位

```text
以下是连载前 {N} 章的大纲或正文：{粘贴材料}
请以付费阅读运营的视角：
1. 标出每个"天然卡点"：{高潮将到未到、真相将揭、阴谋将成} 的位置（第几章第几段）；
2. 对每个卡点评分：付费吸引力（0–10）+ 理由；
3. 选出最强的一个卡点，说明为什么它适合做付费节点；
4. 若现有结构没有合格卡点，给出调整建议（往哪里埋悬念、在哪里断章）；
5. 检查前 1000 字：是否直接进冲突、有无"我叫 XX"式平铺开头，给出开篇修改建议。
```

## 9.6 操作步骤

1. **写完最后一章**：先在正文上下文里跑一遍第 7 章模板 C（近期矛盾清单），把当场能修的小问题修掉。
2. **另起干净上下文**：新建会话，只喂设定集 + 全书（或逐卷），跑模板 A 输出审稿报告。
3. **逐条修复**：另开一个上下文，按模板 B 从【致命】修到【建议】；修完一章回填一章。
4. **程序化检查**：写个小脚本扫描角色名拼写统一性与时间线倒挂（名称表 + 时间线表是脚本的输入）。
5. **试读**：跑模板 C 检查关键章节与开篇；付费文再跑模板 D 定卡点。
6. **转格式发布**：Markdown 定稿后用 Pandoc 转 epub/PDF/HTML（34 本小说经验的发布管线）；需要封面/人物图时可用 AI 生图补视觉。发布到自出版（KDP 等）或连载平台后，按完读率数据复盘迭代。

## 9.7 常见坑 + 解决方法

| 坑 | 现象 | 解法 |
|---|---|---|
| 边写边改 | 正文上下文里让 AI 自我审查，全是"写得很棒" | 审稿必须另起干净上下文（模板 A 起手先立人设"无情编辑"） |
| 修复引入新矛盾 | 改了一处时间线，后面三处跟着错 | 模板 B 第 3 条：先列受影响位置清单再动手 |
| 审稿和修复混在一起 | 报告没出全就开始改，漏掉致命问题 | 两件事两个上下文，先清单后修改 |
| 全篇推倒重写 | 审稿后让 AI"重写一遍"，越写越差 | 只按最小改动逐条修；推倒重写只用于个别失控章节 |
| 不懂卡在哪 | 读者弃坑率奇高，不知道哪章劝退 | 模板 C 试读模拟定位 + 后台完读率数据交叉验证 |
| 发布前没程序化检查 | 角色名前后拼写不一致、日期倒挂漏网 | 名称表 + 时间线表喂给脚本扫描，机械问题不靠人眼 |
