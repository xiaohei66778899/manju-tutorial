# 第 4 章 大纲生成

> **教学目标**：学完本章，你能从一句话创意出发，产出"高概念提案 → 故事梗概 → 章节大纲"三层递进的完整大纲，并让每章大纲自带爽点、钩子和伏笔。

---

## 4.1 大纲为什么要三层递进

直接让 AI"写个大纲"得到的一定是空泛废话。正确做法是三层递进（与 GPT-4 从零写整本实验的四级递进相互印证）：

```text
第 1 层 摘要 Summary    一句话创意 → 覆盖"激励事件 / 重大转折 / 高潮"的故事梗概
第 2 层 大纲 Outline    梗概 → 按经典结构（三幕剧 / 英雄之旅 / 三幕每幕五章）铺成章节骨架
第 3 层 章节 Chapters   每章一句话摘要：本章目标 + 爽点/转折 + 章末钩子
```

每一层都必须在上一层确认满意后再往下走。**首轮输出几乎不可能一次满意**——主流写作工具官方明确说要用"强制要什么 / 禁止不要什么"反复打磨，这是正常流程，不是失败。

## 4.2 三个关键心法

1. **提案要批量**（自出版作者六步法）：先让 AI 批量出高概念卖点（`高概念提案` 模板），反复跑几轮，直到挑出一个"有独特 twist + 强情感 stakes"的。选定了再进入梗概，不要一上来就深挖第一个点子。
2. **大纲要故意写长**（34 本小说经验）：AI 有"偷懒写短"的倾向，章节大纲至少 30 章、每章带字数与情节节拍，用清单/复选框结构逼它写完整，对抗它把故事越写越短的毛病。
3. **大纲是活的，写完要回改**（GPT-4 实验 + 多 Agent 架构）：AI 会即兴把后章场景挪到前章、当章解决冲突。所以每写完几章，就让它回头对照大纲修订——大纲不是一次性产物，是持续维护的文件。

## 4.3 可直接复制的提示词模板

### 模板 A：高概念提案（批量头脑风暴）

```text
给我 {5} 个适合{平台/读者，如：知乎盐选付费读者}的{题材，如：都市重生}高概念卖点。
每个卖点要求：
1. 一句话核心设定（含一个独特 twist，不能是常见套路）；
2. 主角及其内在冲突（一句话）；
3. 情感 stakes——读者为什么会在乎；
4. 一句话开篇钩子（前 1000 字的强悬念）。
不要解释过程，直接列 {5} 条。
```

### 模板 B：故事梗概（三层第 1 层）

```text
以下是选定的高概念卖点：{粘贴模板 A 选中的那一条}
请把它展开成完整故事梗概，必须覆盖：
1. 激励事件（故事从哪一刻真正开始）；
2. 三个重大转折（各一句话，说明如何改变主角处境）；
3. 高潮（最终对决/抉择是什么）；
4. 结局走向（明确写死，不许留"开放式"糊弄）。
梗概控制在 {800–1200} 字。
注意：模糊的结局和转折必须写具体，不要用"命运发生改变"这类空话。
```

### 模板 C：章节大纲（三层第 2 层，网文向）

```text
你是一位深谙{平台}付费逻辑的顶级网文策划。
请基于以下梗概，输出 {15–20} 章、约 {5–8} 万字的完整章节大纲：{粘贴梗概}
强制要求：
1. 第 1 章必须是开篇钩子，前 1000 字抛出最强悬念，直接从冲突切入；
2. 每章必须标注"本章爽点/打脸点"和"章末小钩子"；
3. 第 {3–4} 章之间埋一个超级悬念，作为付费卡点；
4. 中段（第 7–12 章）安排一条功能性支线：既提供{战力/信息升级}，又为{配角/反派}成长或黑化埋伏笔；
5. 明确高潮章与伏笔回收清单。
输出格式（每章一行）：
第 N 章｜一句话核心内容｜本章爽点/悬念｜章末钩子
```

### 模板 D：单章细纲（三层第 3 层）

```text
请把第 {N} 章扩展为详细写作细纲，供下一章扩写直接使用：
章节目标：{一句话，本章要推进什么}
出场人物：{名单，含各自本章状态}
场景清单（每场景 3–6 个，每场景给：地点/一句话目标/关键动作/钩子收尾）：
1. {场景名}：{地点}｜目标：{……}｜关键动作：{……}｜结尾钩子：{……}
……
本章结尾钩子：{用一个反常细节或未落地的决定收束，禁止"主角获得胜利"式收尾}
```

### 模板 E：写完回改大纲（防跑偏）

```text
以下是我刚写完的章节：{粘贴正文或章节摘要}
请对照原有大纲：{粘贴原大纲}
检查并输出：
1. 本章实际发生的事件与原大纲的偏差（逐条列出）；
2. 是否提前使用了后文伏笔或解决了本该后面解决的冲突；
3. 修订版大纲（只改受影响章节，保持其余不变）。
```

## 4.4 操作步骤

1. **跑提案**：用模板 A 连跑 2–3 轮，每轮 5 个卖点，挑中意的那个。
2. **定梗概**：用模板 B 展开；不满意就用"强制要什么/禁止不要什么"的方式指出，反复打磨 2–3 轮，直到梗概的转折和结局都具体可查。
3. **铺章节**：用模板 C 出全书章节大纲（网文向）或模板 D 逐章细化（严肃向）；建议存成 `大纲.md` 文件，每章一行，方便后续回改。
4. **建支线台账**：想保留的支线单独列出来（做法是建独立条目），后续写章节时按需引用，避免写到中段忘掉。
5. **写作中持续回改**：每写 3–5 章，用模板 E 让 AI 对照大纲检查一次并修订大纲文件（GPT-4 实验的"回改大纲"机制）。
6. **专用工具**：FeelFish、灵蟹创作等专用工作台可由大纲一键生成章节框架，并随写随更大纲。

## 4.5 常见坑 + 解决方法

| 坑 | 现象 | 解法 |
|---|---|---|
| 一次要全文大纲 | 输出空泛、套路化 | 三层递进，逐层确认；首轮不满意就"强制/禁止"反复打磨 |
| 大纲越写越短 | 30 章的故事缩成 15 章 | 大纲刻意写长：固定章节数、每章带字数与节拍、用清单逼全 |
| 章节大纲没有钩子 | 每章平铺直叙，读者不追 | 每章强制标注"爽点 + 章末钩子"；章末禁止"主角胜利"式收尾 |
| AI 当章解决冲突 | 后文没得写 | 走向由你定，模板 E 定期回改大纲纠偏 |
| 支线写着写着消失 | 中段疲软、前文伏笔无人回收 | 支线单独建台账，写章节前先查该章要推进哪条线 |
| 梗概结局模糊 | "命运发生改变"式空话 | 模板 B 明确要求写死结局与转折，不许开放式糊弄 |
