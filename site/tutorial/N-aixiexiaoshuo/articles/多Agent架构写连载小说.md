# 用 ChatGPT 写连载小说？这套多 Agent 架构让 AI 告别失忆与 AI 味

- **来源 URL**: https://segmentfault.com/a/1190000047905047
- **作者/站点**: 八块腹肌的香菇（SegmentFault 思否）
- **发布日期**: 2026-06-24

## 核心观点摘要（中文）

作者从工程视角指出：单核大模型写长篇连载必然"剧情暴走、人设崩塌、满屏 AI 塑料味"，根因有二——Transformer 的"中间迷失（Lost in the Middle）"导致几十章前埋的伏笔注意力稀释、角色复活；next-token 概率回归让模型总往最安全的陈词滥调靠（"然而""不可否认""深邃的眼眸""嘴角勾起弧度"）。解法是把创作拆成多 Agent 流水线：**架构师 Agent** 只负责全局大纲/世界观/力量体系的生成与校验；**导演 Agent** 把每卷拆成章节剧情节拍（beat）、分配出场人物与核心冲突；**写手 Agent** 只按导演给的 beat 和设定码字；**审稿 Agent** 负责查重、抓逻辑 Bug、去 AI 味。长篇"失忆"用 RAG+知识图谱解决：维护一个 JSON/向量版动态设定集（Lorebook），写手写新章时自动召回相关角色地点；同时用轻量模型把每章压成 200 字摘要，写手创作第 N 章只读取"全局大纲+第 N-3 至 N-1 章摘要+本章 beat"。去 AI 味两招：建"AI 高频词黑名单"后处理脚本触发局部重写；风格锚定——在提示词里给具体 Few-Shot 示例，甚至用 LoRA 微调一个模仿烽火戏诸侯/猫腻文风的小模型当写手底座。避坑三不要：别让 AI 自己定剧情走向（它会当章把冲突解决掉）、别忽视对话潜台词、别一次性生成一万字（工程极限单次 2000–3000 字）。

## 一句话推荐理由
最硬核的一篇：用多 Agent 分工 + RAG 滑动窗口摘要 + AI 高频词黑名单 + LoRA 风格锚定，系统解决"长篇失忆"和"AI 味"两大顽疾。
